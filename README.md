# nixos-dotfiles

NixOS configuration for my two laptops (one AMD, one Intel): a flake that
builds the whole system and, through Home Manager, the user environment
(Mango WM, Waybar, foot, fish, LazyVim, …). Migrated from my [Arch dotfiles](https://github.com/dcalonge/dotfiles).

## Structure

```text
flake.nix                    inputs, user variables, one nixosConfiguration per host
flake.lock                   exact revisions of every input
configuration.nix            shared system config: boot, nix, networking, audio, desktop, fonts, flatpak
hosts/
  laptop-amd/                AMD CPU/GPU: microcode, early amdgpu, radeonsi VA-API
  laptop-intel/              Intel 7th gen: microcode, iHD VA-API, thermald
    default.nix              drivers and settings for that laptop
    hardware-configuration.nix  generated by nixos-generate-config on that laptop
home/                        Home Manager modules for the user
  default.nix                session variables, packages, tty1 login, user services
  apps.nix                   foot, fuzzel, mako, LazyVim, yazi, zathura, mpv, imv, btop, opencode
  mango.nix                  compositor settings and keybindings
  waybar.nix                 bar layout and style
  shell.nix                  fish (prompt, theme, abbreviations), eza, bat, git tools
  theming.nix                GTK, Qt, cursor and the matugen setup
  matugen/templates/         matugen templates, one per themed app
  matugen/defaults/          initial colour files (the palette from the Arch setup)
  nvim/                      LazyVim config, plugins and colorscheme
  opencode/AGENTS.md         opencode global instructions
pkgs/
  default.nix                overlay: pkgs.helium and pkgs.dotfiles-scripts
  scripts/*.sh               menu, media-key, wallpaper and waybar scripts
```

`flake.nix` has a `vars` block with the user name and the path this repo is
cloned to (`/home/daniel/nixos-dotfiles`); change those there. Each host's
name is also its directory in `hosts/` and its hostname, so `nh os switch`
picks the right configuration on each laptop. To add a host, create
`hosts/<name>/` and add the name to the list in `flake.nix`.

## How it fits together

- **One flake, one rebuild per laptop.** Each of
  `nixosConfigurations.laptop-amd` and `laptop-intel` combines the shared
  `configuration.nix`, its `hosts/<name>/` directory, the overlay in `pkgs/`
  and the Home Manager NixOS module, which builds `home/` for the user. Home
  Manager uses the system's `pkgs`, so the overlay is available everywhere.
  Every config file it generates is a read-only link into the Nix store. If
  a real file is in the way on first activation, Home Manager renames it to
  `*.hm-backup`.
- **Packages come from nixpkgs.** No input is pinned to a tag or branch
  other than `nixos-unstable`. `flake.lock` records exact commits, and
  updating moves every input to its latest one. Helium isn't in nixpkgs, so
  it comes from its own flake and is wrapped in the overlay with the
  Chromium flags from the old `chrome_flags.conf`. Mango is `pkgs.mango`. The
  `mango` flake input is only used for its Home Manager module, which writes
  `~/.config/mango/config.conf` and checks it with `mango -p` at build time,
  so an invalid key or a value over 255 bytes fails the build.
- **Login.** tty1 asks only for the password (`services.getty`). The bash
  login shell then runs `exec mango`. Mango imports the session environment
  into systemd and starts `mango-session.target`, which starts the user
  services that `autostart.sh` used to launch: waybar, swaybg, cliphist,
  swayidle (locks with gtklock before sleep), udiskie and the polkit agent.
  wlsunset is a service too, but it doesn't start with the session;
  `SUPER+s` toggles it.
- **Scripts are packages.** Each `pkgs/scripts/<name>.sh` is built with
  `writeShellApplication`, which puts its dependencies on `PATH` and runs
  shellcheck at build time. `@flakeDir@` is replaced with the repo path.
  They're installed for the user, and keybindings and waybar call them by
  store path.
- **Networking.** iwd associates with Wi-Fi, systemd-networkd does DHCP
  (wired preferred over Wi-Fi) and systemd-resolved serves DNS. Connect with
  `iwctl station wlan0 connect "SSID"` or the `SUPER+w` menu. Credentials
  are kept by iwd, not in this repo.

## Theming

Colours follow the wallpaper, as on Arch:

1. `change-wallpaper` (`SUPER+SHIFT+w`) picks an image: the Bing image of
   the day, a random one or one chosen in yazi, all from `~/Pictures/walls`.
2. It points `~/Pictures/wallpaper` at the image, restarts the `swaybg`
   service and runs matugen.
3. matugen's config is generated in `home/theming.nix` from the templates in
   `home/matugen/templates/`. It writes small colour files such as
   `~/.config/foot/colors.ini` and `~/.config/waybar/colors.css`, then
   reloads the apps.

The main configs are read-only and only *include* those colour files. The
colour files themselves aren't managed by Home Manager, so matugen can
overwrite them. On activation, any colour file that doesn't exist yet is
copied from `home/matugen/defaults/`, so a fresh install starts with a valid
theme.

To theme another app: add a template and a default file, add an entry to
`matugenTargets` in `home/theming.nix`, and include the output file from that
app's config.

## Installing

Check the timezone, locale and keyboard layout in `configuration.nix` first.

### From the NixOS minimal ISO

Boot the ISO, get online, then as root (`sudo -i`). This wipes the disk;
replace `/dev/nvme0n1` with yours (`lsblk`), and set `HOST` to
`laptop-amd` or `laptop-intel`. The labels match the placeholder
`hardware-configuration.nix` files.

```bash
HOST=laptop-amd

parted /dev/nvme0n1 -- mklabel gpt
parted /dev/nvme0n1 -- mkpart root ext4 1GB -8GB
parted /dev/nvme0n1 -- mkpart swap linux-swap -8GB 100%
parted /dev/nvme0n1 -- mkpart ESP fat32 1MB 1GB
parted /dev/nvme0n1 -- set 3 esp on

mkfs.ext4 -L nixos /dev/nvme0n1p1
mkswap -L swap /dev/nvme0n1p2
mkfs.fat -F 32 -n boot /dev/nvme0n1p3

mount /dev/disk/by-label/nixos /mnt
mount --mkdir -o umask=077 /dev/disk/by-label/boot /mnt/boot
swapon /dev/disk/by-label/swap

export NIX_CONFIG="experimental-features = nix-command flakes"
nix-shell -p git --run \
  "git clone https://github.com/dcalonge/nixos-dotfiles /mnt/home/daniel/nixos-dotfiles"
cd /mnt/home/daniel/nixos-dotfiles
nixos-generate-config --root /mnt --show-hardware-config > hosts/$HOST/hardware-configuration.nix
nix-shell -p git --run "git add hosts/$HOST"   # flakes only see tracked files

nixos-install --flake .#$HOST    # asks for the root password at the end
nixos-enter --root /mnt -c 'passwd daniel && chown -R daniel:users /home/daniel'
reboot
```

After rebooting, log in on tty1 with daniel's password; Mango starts
automatically. Connect to Wi-Fi with `iwctl` or `SUPER+w`.

### On an existing NixOS install

```bash
git clone https://github.com/dcalonge/nixos-dotfiles ~/nixos-dotfiles
cd ~/nixos-dotfiles
HOST=laptop-amd    # or laptop-intel
sudo nixos-generate-config --show-hardware-config > hosts/$HOST/hardware-configuration.nix
git add -A
sudo nixos-rebuild switch --flake .#$HOST
sudo passwd daniel    # if the user didn't exist before
```

## Day to day

| Task | Command |
| --- | --- |
| Apply config changes | `nh os switch` (`pb`) |
| Update all inputs and switch | `nh os switch --update` (`pu`), or `SUPER+u` |
| Search packages | `nh search <name>` (`ps`) |
| Try a package without installing it | `nix shell nixpkgs#<name>` (`pi`) |
| Format the repo | `nix fmt` |

The waybar updates module shows when `nixos-unstable` has moved past the
locked revision, and lists pending Flatpak updates. Old generations are
garbage-collected weekly by `programs.nh.clean`, which keeps the last 14
days and at least 5 generations.

- **Install a package:** add it to `home.packages` in `home/default.nix`
  (user) or `environment.systemPackages` in `configuration.nix` (system).
  If Home Manager has a `programs.<name>` module, prefer that. Then switch.
- **Install a Flatpak:** add its ID to `services.flatpak.packages` in
  `configuration.nix`. Apps installed by hand with `flatpak install` are
  left alone.
- **Change app settings:** edit the Nix module, not the file in `~/.config`,
  which is read-only. This also applies to btop's options menu and to GTK
  settings.
- **Neovim:** LazyVim comes from
  [lazyvim-nix](https://github.com/pfassina/lazyvim-nix). Plugins and
  treesitter parsers come from Nix (nixpkgs builds where possible), and
  Mason isn't used. Put Lua config in `home/nvim/config/` and plugin specs in
  `home/nvim/plugins/`. Add language servers and formatters to
  `programs.lazyvim.extraPackages` in `home/apps.nix`.
- **Add a script:** create `pkgs/scripts/<name>.sh` (no shebang) and
  register it in `pkgs/default.nix` with the packages it needs. It's then
  available as `<name>` and as `pkgs.dotfiles-scripts.<name>`.
