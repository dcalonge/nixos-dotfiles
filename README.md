# nixos-dotfiles

NixOS configuration for my two laptops (one AMD, one Intel): a flake that
builds the system and, through Home Manager, the user environment (Mango WM,
Waybar, foot, fish, Neovim, …). Migrated from my
[Arch dotfiles](https://github.com/dcalonge/dotfiles).

## Structure

```text
flake.nix                    inputs, user variables, one nixosConfiguration per host
flake.lock                   exact revisions of every input
hosts/
  laptop-amd/                AMD CPU/GPU: microcode, early amdgpu, radeonsi VA-API
  laptop-intel/              Intel 7th gen: microcode, iHD VA-API, thermald
    configuration.nix        drivers, zram and swapfile for that laptop
    home.nix                 per-laptop user settings (display scale, mpv decoding)
    hardware-configuration.nix  generated by nixos-generate-config
modules/
  nixos/                     shared system config, imported by every host
    base.nix                 boot, nix, nh, locale, doas, user, tty login
    networking.nix           iwd, systemd-networkd, resolved
    hardware.nix             firmware, bluetooth, graphics, power services
    audio.nix                PipeWire
    desktop.nix              Mango, portals, gtklock, polkit
    fonts.nix                fonts
    flatpak.nix              nix-flatpak and the Flatpak list
    packages.nix             system-wide packages
  home-manager/              Home Manager modules for the user
    session.nix              session variables, packages, tty1 login, user services
    firefox.nix              Firefox, extensions, Betterfox, Pywalfox
    media.nix                zathura, mpv, imv
    desktop/                 mango (compositor, keybindings), waybar, fuzzel, mako
    terminal/                foot, fish (shell.nix), yazi, btop
    neovim/                  Nixvim config modelled on LazyVim; files/ has the matugen colorscheme
    opencode/                opencode settings and AGENTS.md
    theming/                 GTK, Qt, cursor and matugen (templates/ and defaults/ per app)
pkgs/
  default.nix                overlay: pkgs.dotfiles-scripts
  scripts/*.sh               menu, media-key, wallpaper and waybar scripts
```

`flake.nix` has a `vars` block with the user name and the clone path
(`/home/daniel/nixos-dotfiles`). A host's name is its directory in `hosts/` and
its hostname, so `nh os switch` picks the right configuration. To add a host,
create `hosts/<name>/` with a `configuration.nix` and `home.nix`; the flake
finds it by itself.

Files in `modules/nixos/`, `modules/home-manager/` and its `desktop/`,
`terminal/` and `neovim/` subfolders are imported automatically, as are
subfolders with a `default.nix`. Files in `neovim/` are Nixvim modules, not
Home Manager ones. `theming/` and `opencode/` are single modules that list
their own files.

On every push, GitHub Actions runs `nix flake check` (evaluates both hosts)
and checks formatting.

### Enabling or disabling modules per host

Every module is imported for every host. To let a host opt out, give the
module an enable option that defaults to `true` and wrap its config in
`lib.mkIf`:

```nix
# modules/nixos/gaming.nix
{ config, lib, ... }:
{
  options.features.gaming.enable = lib.mkEnableOption "gaming setup" // {
    default = true;
  };

  config = lib.mkIf config.features.gaming.enable {
    programs.steam.enable = true;
  };
}
```

Every host then gets the module; turn it off on one laptop in its host file:

```nix
# hosts/laptop-intel/configuration.nix
{
  features.gaming.enable = false;
}
```

For a module most hosts shouldn't have, drop `default = true` and set
`features.<name>.enable = true;` where wanted. Home Manager modules work the
same way, with the option set in `hosts/<name>/home.nix`. Settings for a single
laptop can just go in its `configuration.nix` or `home.nix`, like the GPU
drivers and display scale. No current module has an enable option, since both
laptops share all of them.

## How it fits together

- **One flake, one rebuild per laptop.** Each `nixosConfigurations.<host>`
  combines `modules/nixos/`, `hosts/<name>/`, the overlay in `pkgs/` and the
  Home Manager NixOS module (which builds `modules/home-manager/`). Home
  Manager uses the system's `pkgs`, so the overlay is available everywhere.
  Generated config files are read-only links into the Nix store; a real file
  in the way on first activation is renamed to `*.hm-backup`.
- **Packages come from nixpkgs.** `flake.lock` pins exact commits; updating
  moves every input to its latest. Firefox gets
  [Betterfox](https://github.com/yokoffing/Betterfox)'s `user.js` from a
  non-flake input and its extensions through the policy
  (`policies.ExtensionSettings`). Mango is `pkgs.mango`; the `mango` flake
  input is only used for its Home Manager module, which writes
  `~/.config/mango/config.conf` and checks it with `mango -p` at build time,
  so an invalid key fails the build.
- **Login.** tty1 asks only for the password (`services.getty`), then the bash
  login shell runs `exec mango`. Mango starts `mango-session.target`, which
  runs waybar, swaybg, cliphist, swayidle, udiskie and the polkit agent as user
  services. wlsunset is one too but only starts on demand (`SUPER+s`).
- **Scripts are packages.** Each `pkgs/scripts/<name>.sh` is built with
  `writeShellApplication`, which puts its dependencies on `PATH` and runs
  shellcheck at build time. `@flakeDir@` is replaced with the repo path.
  Keybindings and waybar call them by store path.

## Theming

Colours follow the wallpaper, as on Arch:

1. `change-wallpaper` (`SUPER+SHIFT+w`) picks an image from
   `~/Pictures/walls` (Bing image of the day, a random one, or one chosen in
   yazi).
2. It points `~/Pictures/wallpaper` at it, restarts the `swaybg` service and
   runs matugen.
3. matugen's config is generated in `modules/home-manager/theming/default.nix`
   from `theming/matugen/templates/`. It writes small colour files such as
   `~/.config/foot/colors.ini` and `~/.config/waybar/colors.css`, then reloads
   the apps.

The main configs are read-only and only *include* those colour files, which
Home Manager doesn't manage, so matugen can overwrite them. On activation,
missing colour files are copied from `theming/matugen/defaults/`, so a fresh
install starts with a valid theme.

To theme another app: add a template and a default file, add an entry to
`matugenTargets` in `theming/default.nix`, and include the output file from
that app's config.

## Installing

Check the timezone, locale and keyboard layout in `modules/nixos/base.nix`
first.

### From the NixOS minimal ISO

Boot the ISO, get online, then as root (`sudo -i`). This wipes the disk:
replace `/dev/nvme0n1` with yours (`lsblk`) and set `HOST` to `laptop-amd` or
`laptop-intel`. The labels match the placeholder `hardware-configuration.nix`
files.

```bash
HOST=laptop-amd

parted /dev/nvme0n1 -- mklabel gpt
parted /dev/nvme0n1 -- mkpart root ext4 1GB 100%
parted /dev/nvme0n1 -- mkpart ESP fat32 1MB 1GB
parted /dev/nvme0n1 -- set 2 esp on

mkfs.ext4 -L nixos /dev/nvme0n1p1
mkfs.fat -F 32 -n boot /dev/nvme0n1p2

mount /dev/disk/by-label/nixos /mnt
mount --mkdir -o umask=077 /dev/disk/by-label/boot /mnt/boot

export NIX_CONFIG="experimental-features = nix-command flakes"
nix-shell -p git --run \
  "git clone https://github.com/dcalonge/nixos-dotfiles /mnt/home/daniel/nixos-dotfiles"
cd /mnt/home/daniel/nixos-dotfiles
nixos-generate-config --root /mnt --show-hardware-config > hosts/$HOST/hardware-configuration.nix
nix-shell -p git --run "git add hosts/$HOST"   # flakes only see tracked files

nixos-install --flake .#$HOST    # asks for the root password at the end
nixos-enter --root /mnt -c 'passwd daniel && chown -R daniel:users /home/daniel'
reboot
```

After rebooting, log in on tty1 with daniel's password; Mango starts
automatically. Connect to Wi-Fi with `iwctl` or `SUPER+w`.

### On an existing NixOS install

The first switch still uses `sudo`, because the current system doesn't have
`doas` yet. Activating the config installs `doas` and removes `sudo`.

```bash
git clone https://github.com/dcalonge/nixos-dotfiles ~/nixos-dotfiles
cd ~/nixos-dotfiles
HOST=laptop-amd    # or laptop-intel
sudo nixos-generate-config --show-hardware-config > hosts/$HOST/hardware-configuration.nix
git add -A
sudo nixos-rebuild switch --flake .#$HOST
sudo passwd daniel    # if the user didn't exist before
```

## Day to day

| Task | Command |
| --- | --- |
| Apply config changes | `nh os switch` (`pb`) |
| Update all inputs and switch | `nh os switch --update` (`pu`), or `SUPER+u` |
| Search packages | `nh search <name>` (`ps`) |
| Try a package without installing it | `nix shell nixpkgs#<name>` (`pi`) |
| Format the repo | `nix fmt` |

The waybar updates module shows pending `nixos-unstable` and Flatpak updates.
`programs.nh.clean` garbage-collects weekly, keeping the last 14 days and at
least 5 generations.

- **Install a package:** add it to `home.packages` in
  `modules/home-manager/session.nix` (user) or `environment.systemPackages` in
  `modules/nixos/packages.nix` (system). Prefer a Home Manager `programs.<name>`
  module when there is one. Then switch.
- **Install a Flatpak:** add its ID to `services.flatpak.packages` in
  `modules/nixos/flatpak.nix`. Apps installed by hand with `flatpak install`
  are left alone.
- **Change app settings:** edit the Nix module, not the read-only file in
  `~/.config` (this includes btop's options menu and GTK settings).
- **Neovim:** a [Nixvim](https://github.com/nix-community/nixvim) setup that
  mirrors LazyVim, with every plugin and treesitter parser coming from Nix (no
  lazy.nvim or Mason). Settings are split by area in
  `modules/home-manager/neovim/`. In those files, enable a plugin with
  `plugins.<name>.enable`, add language servers under `lsp.servers` and
  formatters to `extraPackages`.
- **Add a script:** create `pkgs/scripts/<name>.sh` (no shebang) and register
  it in `pkgs/default.nix` with its packages. It's then available as `<name>`
  and as `pkgs.dotfiles-scripts.<name>`.
