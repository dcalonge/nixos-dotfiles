# nixos-dotfiles

NixOS configuration for my two laptops (one AMD, one Intel): a flake that
builds the system and, through Home Manager, the user environment (Mango WM,
Waybar, foot, fish, Neovim, …). Migrated from my
[Arch dotfiles](https://github.com/dcalonge/dotfiles).

## Structure

The flake uses [flake-parts](https://flake.parts) with the
[dendritic pattern](https://github.com/mightyiam/dendritic): every `.nix` file
under `modules/` is a flake-parts module, loaded automatically by
[import-tree](https://github.com/denful/import-tree) (paths containing `/_` are
skipped). Each file implements one feature, named by its path, for every
configuration it applies to: it adds NixOS and Home Manager settings to a few
shared modules in `flake.modules`.

| Module | Contents |
| --- | --- |
| `nixos.base`, `homeManager.base` | what every machine gets: boot, nix, user, networking, fish, CLI tools, Neovim, opencode |
| `nixos.desktop`, `homeManager.desktop` | the graphical setup: Mango, Waybar, audio, fonts, Firefox, theming, scripts |
| `nixos.<host>` | one machine: hardware config, hostname, drivers, swap, per-laptop user settings |
| `nixvim.neovim` | Nixvim settings, loaded into `programs.nixvim` by `neovim/neovim.nix` |

`home-manager.nix` makes `nixos.base` and `nixos.desktop` bring their Home
Manager counterpart for the user.

```text
flake.nix                    inputs; outputs = every module under modules/
flake.lock                   exact revisions of every input
modules/
  flake-parts.nix            flake.modules, systems, formatter
  user.nix                   user name and clone path (/home/daniel/nixos-dotfiles)
  home-manager.nix           Home Manager NixOS module, wired to base/desktop
  hosts/
    laptop-amd/              AMD CPU/GPU: microcode, early amdgpu, radeonsi VA-API
    laptop-intel/            Intel 7th gen: microcode, iHD VA-API, thermald
      configuration.nix      nixosConfigurations.<host> and its drivers, zram, swapfile
      home.nix               per-laptop user settings (display scale, mpv decoding)
      _hardware-configuration.nix  generated by nixos-generate-config
  system/                    base (boot, nix, nh, locale, doas, user, tty login),
                             networking, packages, hardware, audio, fonts, flatpak
  desktop/                   mango, session (user services, login), lock (gtklock +
                             swayidle), waybar, fuzzel, mako
  terminal/                  foot, shell (fish), tools (yazi, btop)
  apps/                      firefox, media (zathura, mpv, imv), opencode
  neovim/                    Nixvim config modelled on LazyVim; files/ has the colorscheme
  theming/                   GTK, Qt, cursor and matugen (templates/ and defaults/ per app)
  scripts/                   overlay: pkgs.dotfiles-scripts, built from the *.sh files
```

Files share values through the flake-parts `config` (the user name in
`user.nix`, used by `system/base.nix`) and flake inputs through its `inputs`
argument, never through `specialArgs`. A new feature is a new file anywhere
under `modules/`:

```nix
# modules/apps/printing.nix
{
  flake.modules.nixos.desktop = {
    services.printing.enable = true;
  };

  flake.modules.homeManager.desktop =
    { pkgs, ... }:
    {
      home.packages = [ pkgs.system-config-printer ];
    };
}
```

On every push, GitHub Actions runs `nix flake check` (evaluates both hosts)
and checks formatting.

### Choosing modules per host

A host gets exactly the modules its `configuration.nix` lists; importing a
module enables everything in it:

```nix
# modules/hosts/laptop-amd/configuration.nix
flake.nixosConfigurations.laptop-amd = inputs.nixpkgs.lib.nixosSystem {
  modules = [
    nixos.base
    nixos.desktop
    nixos.laptop-amd
  ];
};
```

`base` and `desktop` hold only what every host using them shares. Anything
that not every host should have goes into its own module instead, and only the
hosts that want it list it:

```nix
# modules/apps/gaming.nix
{
  flake.modules.nixos.gaming = {
    programs.steam.enable = true;
  };
}
```

```nix
# modules/hosts/laptop-amd/configuration.nix
modules = [
  nixos.base
  nixos.desktop
  nixos.gaming
  nixos.laptop-amd
];
```

If a shared feature stops being wanted on one laptop, move it out of `desktop`
into its own module the same way and list it on the hosts that keep it. Settings
for a single laptop go in `flake.modules.nixos.<host>` (user settings under
`home-manager.users.<user>`, as in `home.nix`). To add a host, copy one of the
`modules/hosts/` folders and change the names.

## How it fits together

- **One flake, one rebuild per laptop.** Each `nixosConfigurations.<host>`
  combines the modules its host file lists, and the Home Manager NixOS module
  builds the matching Home Manager modules for the user. Home
  Manager uses the system's `pkgs`, so the scripts overlay is available
  everywhere. Generated config files are read-only links into the Nix store; a
  real file in the way on first activation is renamed to `*.hm-backup`.
- **Packages come from nixpkgs.** `flake.lock` pins exact commits; updating
  moves every input to its latest. Firefox gets
  [Betterfox](https://github.com/yokoffing/Betterfox)'s `user.js` from a
  non-flake input and its extensions through the policy
  (`policies.ExtensionSettings`). Mango is `pkgs.mango`; the `mango` flake
  input is only used for its Home Manager module, which writes
  `~/.config/mango/config.conf` and checks it with `mango -p` at build time,
  so an invalid key fails the build.
- **Login.** tty1 asks only for the password (`services.getty`), then the bash
  login shell runs `exec mango`. Mango starts `mango-session.target`, which
  runs waybar, swaybg, cliphist, swayidle, udiskie and the polkit agent as user
  services. wlsunset is one too but only starts on demand (`SUPER+s`).
- **Scripts are packages.** Each `modules/scripts/<name>.sh` is built with
  `writeShellApplication`, which puts its dependencies on `PATH` and runs
  shellcheck at build time. `@flakeDir@` is replaced with the repo path.
  Keybindings and waybar call them by store path.

## Theming

Colours follow the wallpaper, as on Arch:

1. `change-wallpaper` (`SUPER+SHIFT+w`) picks an image from
   `~/Pictures/walls` (Bing image of the day, a random one, or one chosen in
   yazi).
2. It points `~/Pictures/wallpaper` at it, restarts the `swaybg` service and
   runs matugen.
3. matugen's config is generated in `modules/theming/theming.nix` from
   `theming/matugen/templates/`. It writes small colour files such as
   `~/.config/foot/colors.ini` and `~/.config/waybar/colors.css`, then reloads
   the apps.

The main configs are read-only and only *include* those colour files, which
Home Manager doesn't manage, so matugen can overwrite them. On activation,
missing colour files are copied from `theming/matugen/defaults/`, so a fresh
install starts with a valid theme.

To theme another app: add a template and a default file, add an entry to
`matugenTargets` in `theming/theming.nix`, and include the output file from
that app's config.

## Installing

Check the timezone, locale and keyboard layout in `modules/system/base.nix`
first.

### From the NixOS minimal ISO

Boot the ISO, get online, then as root (`sudo -i`). This wipes the disk:
replace `/dev/nvme0n1` with yours (`lsblk`) and set `HOST` to `laptop-amd` or
`laptop-intel`. The labels match the placeholder `_hardware-configuration.nix`
files.

```bash
HOST=laptop-amd

parted /dev/nvme0n1 -- mklabel gpt
parted /dev/nvme0n1 -- mkpart root ext4 1GB 100%
parted /dev/nvme0n1 -- mkpart ESP fat32 1MB 1GB
parted /dev/nvme0n1 -- set 2 esp on

mkfs.ext4 -L nixos /dev/nvme0n1p1
mkfs.fat -F 32 -n boot /dev/nvme0n1p2

mount /dev/disk/by-label/nixos /mnt
mount --mkdir -o umask=077 /dev/disk/by-label/boot /mnt/boot

export NIX_CONFIG="experimental-features = nix-command flakes"
nix-shell -p git --run \
  "git clone https://github.com/dcalonge/nixos-dotfiles /mnt/home/daniel/nixos-dotfiles"
cd /mnt/home/daniel/nixos-dotfiles
nixos-generate-config --root /mnt --show-hardware-config > modules/hosts/$HOST/_hardware-configuration.nix
nix-shell -p git --run "git add modules/hosts/$HOST"   # flakes only see tracked files

nixos-install --flake .#$HOST    # asks for the root password at the end
nixos-enter --root /mnt -c 'passwd daniel && chown -R daniel:users /home/daniel'
reboot
```

After rebooting, log in on tty1 with daniel's password; Mango starts
automatically. Connect to Wi-Fi with `iwctl` or `SUPER+w`.

### On an existing NixOS install

The first switch still uses `sudo`, because the current system doesn't have
`doas` yet. Activating the config installs `doas` and removes `sudo`.

```bash
git clone https://github.com/dcalonge/nixos-dotfiles ~/nixos-dotfiles
cd ~/nixos-dotfiles
HOST=laptop-amd    # or laptop-intel
sudo nixos-generate-config --show-hardware-config > modules/hosts/$HOST/_hardware-configuration.nix
git add -A
sudo nixos-rebuild switch --flake .#$HOST
sudo passwd daniel    # if the user didn't exist before
```

## Day to day

| Task | Command |
| --- | --- |
| Apply config changes | `nh os switch` (`pb`) |
| Update all inputs and switch | `nh os switch --update` (`pu`), or `SUPER+u` |
| Search packages | `nh search <name>` (`ps`) |
| Try a package without installing it | `nix shell nixpkgs#<name>` (`pi`) |
| Format the repo | `nix fmt` |

The waybar updates module shows pending `nixos-unstable` and Flatpak updates.
`programs.nh.clean` garbage-collects weekly, keeping the last 14 days and at
least 5 generations.

- **Install a package:** add it to `home.packages` in
  `modules/desktop/session.nix` (user) or `environment.systemPackages` in
  `modules/system/packages.nix` (system), or give it its own feature file.
  Prefer a Home Manager `programs.<name>` module when there is one. Then switch.
- **Install a Flatpak:** add its ID to `services.flatpak.packages` in
  `modules/system/flatpak.nix`. Apps installed by hand with `flatpak install`
  are left alone.
- **Change app settings:** edit the Nix module, not the read-only file in
  `~/.config` (this includes btop's options menu and GTK settings).
- **Neovim:** a [Nixvim](https://github.com/nix-community/nixvim) setup that
  mirrors LazyVim, with every plugin and treesitter parser coming from Nix (no
  lazy.nvim or Mason). Settings are split by area in `modules/neovim/`. In
  those files, enable a plugin with `plugins.<name>.enable`, add language
  servers under `lsp.servers` and formatters to `extraPackages`.
- **Add a script:** create `modules/scripts/<name>.sh` (no shebang) and
  register it in `modules/scripts/scripts.nix` with its packages. It's then
  available as `<name>` and as `pkgs.dotfiles-scripts.<name>`.
